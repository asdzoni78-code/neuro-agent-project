## 0. Как пользоваться планом

**Легенда статусов:** `⬜ не начато` · `🟡 в работе` · `✅ готово` · `🔴 блокер`

**Правило работы:** идём строго по фазам сверху вниз. Фаза считается закрытой
только когда выполнены все её критерии готовности. После закрытия фазы —
обновляем этот файл (см. раздел 8 «Автообновление»).

**Аналогия:** план — как чек-лист сборки шкафа. Сначала каркас (стенки), потом
полки, потом дверцы. Нельзя вешать дверцы, пока нет каркаса — поэтому фазы идут
по порядку, и у каждой есть «зависит от».

## 1. Обзор и итоговое состояние

После всех фаз получаем рабочее приложение:
- **3 экрана**: помещения → ввод замера → сравнение (без сборки, открывается через `file://`).
- **Двухстадийный расчёт**: фактическая толщина материала из разницы замеров ДО/ПОСЛЕ.
- **AI-отчёт** через Claude Opus (`claude-opus-4-8`) в модалке приложения.
- **Две доставки в Telegram** Максиму (алерт + полный отчёт).
- **Понятная обработка ошибок**: при сбое AI — резервный отчёт по цифрам; при сбое
  Telegram — кнопка повторной отправки. Пользователь всегда видит русский текст, а
  не техническую ошибку.
- **Ключи вне git**: `config.js` в `.gitignore`.

Стек: Vanilla JS + HTML/CSS, localStorage (`zamery_v1`), fetch прямо из браузера.
Подробности — в `SPEC.md` и `idea.md`.

## 4. Обработка ошибок LLM и Telegram

**Принцип:** пользователь видит только понятный русский текст. Технические детали
(статус-коды, тела ответов, стеки) идут в `console.error` для разработчика (F12).

Реализация — две вспомогательные функции в `ai-agent.js`:
- `showUserError(msgRu)` — рендерит русское сообщение в модалку.
- `logDev(tag, err)` — обёртка над `console.error` (тег + детали).
- Все `fetch` — в `try/catch`, с `AbortController` для таймаута (60 c).

### 4.1. Ошибки Claude (LLM)

| Сценарий | Сообщение пользователю (RU) | Лог разработчику | Действие |
|---|---|---|---|
| Нет сети / fetch failed | «Нет связи с интернетом. Проверьте подключение и нажмите «Повторить».» | `[LLM] network` + err | кнопка «Повторить» |
| 401 / неверный ключ | «Проблема с доступом к сервису отчётов. Сообщите Александру.» | `[LLM] 401` + тело | «Повторить» неактивна |
| 429 / 529 перегрузка | «Сервис перегружен. Попробуйте через минуту.» | `[LLM] 429/529` | «Повторить» |
| 500 / 5xx | «Сервис отчётов временно недоступен. Попробуйте позже.» | `[LLM] 5xx` + тело | «Повторить» |
| Таймаут (>60 c) | «Отчёт формируется слишком долго. Попробуйте ещё раз.» | `[LLM] timeout` | «Повторить» |
| Пустой / битый ответ | «Не удалось получить текст отчёта.» | `[LLM] bad response` + JSON | «Повторить» |

**Локальный отчёт-резерв** (решение заказчика): при **любой** ошибке выше
приложение не оставляет пользователя ни с чем. Функция `buildFallbackReport()`
собирает отчёт **только из уже посчитанных цифр** (объект, перерасходы по
помещениям/материалам, ответственные) — без обращения к Claude. Показывается в
той же модалке с пометкой:

> ⚠️ _«Показан резервный отчёт по цифрам (без анализа AI). Нажмите «Повторить», чтобы сформировать полный отчёт.»_

### 4.2. Ошибки Telegram

Отчёт **всегда остаётся виден в модалке приложения.** Отправка в TG — отдельный
шаг с собственной кнопкой повтора; повтор отправки **не пересоздаёт** отчёт.

| Сценарий | Сообщение пользователю (RU) | Лог | Действие |
|---|---|---|---|
| Сбой sendMessage (сеть/HTTP) | «Отчёт готов, но не отправился в Telegram. Нажмите «Повторить отправку».» | `[TG]` + resp | кнопка «Повторить отправку» |
| Ушло 1-е, не ушло 2-е | «Отправлено частично. Повторить отправку полного отчёта?» | какой из двух упал | повтор только неудачного |
| Неверный chat_id / токен | «Не удаётся отправить Максиму. Проверьте настройки (Александр).» | тело ответа TG | повтор неактивен |

## 7. Как тестировать (сквозной сценарий)

1. Открыть `index.html` в Chrome → DevTools → эмуляция iPhone.
2. Добавить этаж → комнату → ввести стадию 1 → проверить площадь пола.
3. Ввести стадию 2 → проверить толщину (Δ высоты; Δ длины/ширины / 2).
4. Экран 3 → сверить цифры с ручным расчётом по формулам SPEC.md.
5. Перезагрузить страницу → данные на месте.
6. Ввести факт > плана → строка красная (`#dc3545`).
7. Нажать «Сформировать отчёт» → спиннер → текст отчёта в модалке.
8. Проверить TG Максима: два сообщения (алерт + полный).
9. `git status` → `config.js` не в списке.

**Проверка ветки ошибок (обязательно):**
10. Временно испортить ключ в `config.js` → нажать «Сформировать отчёт» →
    убедиться, что показан **резервный отчёт по цифрам** и русское сообщение
    (без технического текста), кнопка «Повторить» на месте.
11. Временно испортить `TG_BOT_TOKEN` → убедиться, что отчёт **остался виден**, а
    появилось сообщение и кнопка «Повторить отправку».
