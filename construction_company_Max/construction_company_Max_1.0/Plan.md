# Plan.md — План реализации «СтройАудит» v2.0

_Дата: 2026-07-04 | Статус: **v1.0 ✅ готова** · **v2.0 ⬜ ожидает старта** | Источник правды по статусу — этот файл_

Работаем строго по фазам сверху вниз. Фаза закрыта только когда выполнены все её
критерии готовности. После закрытия фазы — обновляем этот файл (раздел «Автообновление»).

**Легенда статусов:** `⬜ не начато` · `🟡 в работе` · `✅ готово` · `🔴 блокер`

**Аналогия:** план — чек-лист сборки. Нельзя вешать дверцы, пока нет каркаса —
поэтому фазы идут по порядку, и у каждой есть «зависит от».

## 2. Задачи по фазам

### Ф6. Доверие к цифрам ✅
**Цель:** цифры в «Сравнении» корректны и не вводят в заблуждение. **Зависит от:** —

| Задача | Файл(ы) | Тест | Статус |
|---|---|---|---|
| Баг «штукатурка ЦПС: недорасход вместо перерасхода» | `app.js` | Проём > стены не даёт отрицательный расход (Тест 8) | ✅ |
| «Итого по объекту» — убрать сумму тонн разных материалов | `app.js` | В строке «Итого» тонны не суммируются между материалами | ✅ |
| Итог по объекту — только в ₽ | `app.js` | Объектный итог показывает только рубли | ✅ |

**Разбор #15 (по данным заказчика):** причина — опечатка в замере (окно ст.2, стена В:
высота `14960` вместо `1460`) → площадь «окна» 37,25 м² > площади стены 12,74 м² →
чистая площадь −24,5 м² → расход стены −2,21 т. Этот минус маскировал перерасход трёх
других стен, утаскивая итог штукатурки ЦПС с ~2,37 т до 0,166 т.
**Настоящий баг в коде:** `calcWall` допускал отрицательную чистую площадь. Исправлено —
`planNet`/`factNet` ограничены снизу нулём (`Math.max(0, …)`). Опечатку в данных заказчик
правит вручную; подсветку «проём > стены» добавит валидация Ф10.

**Критерии готовности:** [x] баг устранён и покрыт тестом; [x] объектный итог — только ₽; [x] тонны не смешиваются.

## 4. Обработка ошибок (сводка — детали в SPEC.md р.8)

Принцип: пользователь видит **только русский текст**, техника — в `console.error`
(`logDev`) и логах сервера.
- **LLM (Claude):** сеть / 401 / 429-529 / 5xx / таймаут / битый ответ → русские сообщения + резервный отчёт по цифрам (`buildFallbackReport`). Таблица 4.1 v1.0 — в силе.
- **Telegram:** сбой отправки / частично / неверный chat_id → «Повторить отправку», отчёт не теряется. Таблица 4.2 v1.0 — в силе.
- **Сервер/сессия (новое, Ф12):** нет связи / сессия истекла / нет прав / сбой сохранения → русские сообщения (SPEC 8), локальный кэш как страховка.
