# Спецификация: «Замеры и перерасход» + AI-агент

_Дата: 2026-07-01 | Статус: Готово к разработке_

---

## Executive Summary

Веб-приложение для Александра и его клиента Максима.  
Прораб вводит размеры помещения на двух стадиях — система сама считает фактическую толщину материала и выявляет приписки.  
AI-агент (Claude Opus) генерирует деловой отчёт о перерасходе и отправляет его Максиму в Telegram двумя сообщениями.

---

## Проблема

«Заложили 10 см штукатурки, сделали 8, записали 10» — прораб завышает объём, и никто не видит.  
Все конкуренты (Gectaro, HeavyJob, Raken, ПУСК) **верят введённой цифре прораба**.  
Единственный способ поймать приписку — сравнить физические размеры помещения ДО и ПОСЛЕ работ.  
Это и есть рыночный пробел: мост между «инструментом замера» и «учётом расхода», которого нет ни у кого.

## Ключевые формулы

### Пол
```
area_m2          = (length × width) / 1_000_000
thickness_s1_cm  = thicknessPlan_mm / 10
thickness_s2_cm  = (height_s1 − height_s2) / 10      ← дельта высот
consumption_t    = area_m2 × thickness_cm × norm / 1000
```

### Высота стены для расчёта площади
```
Стадия 1 (план):  wall_height = height_s1   (всегда)

Стадия 2 (факт):
  screed_first  → wall_height = height_s2
  plaster_first → wall_height = height_s1
  unknown       → wall_height = height_s1
```

### Площадь стены нетто
```
Стены А и В: wall_width = length (текущей стадии)
Стены Б и Г: wall_width = width  (текущей стадии)

gross    = (wall_height × wall_width) / 1_000_000
openings = Σ(opening.w × opening.h) / 1_000_000
net_area = gross − openings
```

### Толщина стен стадии 2
```
thickness_AV_mm = (length_s1 − length_s2) / 2
thickness_BG_mm = (width_s1  − width_s2)  / 2
```

### Расход стены
```
consumption_t = net_area_m2 × (thickness_mm / 10) × norm / 1000
```

### Откосы и колонны
```
откос:   area_m2 = (perimeter × slope_width) / 1_000_000
колонна: area_m2 = (perimeter × height) / 1_000_000
consumption_t = area_m2 × (thickness_mm / 10) × norm / 1000
```

## Экраны

### Навигация
- **Мобайл:** нижняя панель с 3 иконками (Помещения / Замер / Сравнение)
- **Десктоп:** горизонтальные вкладки сверху

### Экран 1 — Объект и помещения
- Название объекта (редактируемый заголовок)
- Список этажей → список помещений (аккордеон)
- Кнопки «+ Этаж», «+ Помещение»
- У каждого помещения: название + индикаторы стадий (● ст.1 / ○ ст.2)

### Экран 2 — Ввод замера
1. Название помещения + переключатель [Стадия 1] / [Стадия 2]
2. **Общие размеры:** Высота / Длина А→В / Ширина Б→Г в мм (`inputmode="numeric"`)
3. **Порядок работ:** radio (Стяжка раньше / Штукатурка раньше / Не указано)
4. **Пол:** материал + план.толщина (ст.1) / авторасчёт (ст.2, read-only)
5. **Потолок:** заглушка «Не активен в пилоте»
6. **Стены А, Б, В, Г** (раскрывающиеся блоки):
   - Проёмы: тип / ширина / высота + «+ Проём»
   - Материал (select)
   - Толщина: ст.1 → input; ст.2 → авторасчёт
7. **Откосы:** список + «+ Откос» (тип, периметр, ширина, материал, толщина)
8. **Колонны:** список + «+ Колонна» (периметр, высота, материал, толщина)
9. **Ответственный:** текстовое поле (свободный ввод)
10. **Фото:** кнопка disabled, подпись «скоро»

**Реактивность:** любое изменение → мгновенный пересчёт + сохранение в localStorage.

### Экран 3 — Сравнение

**Мобайл — 3 вкладки:**
| Вкладка | Колонки |
|---|---|
| План | Материал · Смета,т · План,т · Ответственный |
| Факт | Материал · Факт,т · Ответственный |
| Расхождение | Материал · Δт · Δ₽ · % · Ответственный |

**Десктоп — одна таблица:**
`Материал | Смета,т | План,т | Факт,т | Δт | Δ₽ | % | Ответственный`

- Разбивка (аккордеон): Объект → Этаж → Помещение → Поверхность
- Перерасход (Δ < 0) — строка красная (`#dc3545`)
- Итоговая строка по объекту
- Оффлайн-индикатор (sticky-баннер): оранжевый «Офлайн» / зелёный «Сохранено»
- **Кнопка «Сформировать отчёт»** — внизу, всегда видна

## Компонент 2: AI-агент

### Триггер
Александр нажимает **«Сформировать отчёт»** на экране 3 — вручную, когда данные готовы.

### Процесс (ai-agent.js)
1. Читает расхождения из localStorage
2. Формирует промпт с данными по объекту
3. Вызывает **Claude claude-opus-4-8** (Anthropic API)
4. Показывает отчёт в модалке внутри приложения
5. Отправляет **два TG-сообщения** Максиму

### Структура отчёта
```
ОБЪЕКТ: [название] | ДАТА: [дата]

ПЕРЕРАСХОД:
• [Помещение] / [Материал]: план X т → факт Y т, −Z т (−N%) | Ответственный: [имя]

ОЦЕНКА:
[2–3 предложения: что происходит, насколько серьёзно]

РЕКОМЕНДАЦИИ:
1. [Конкретное действие]
2. [Конкретное действие]
```

### Два TG-сообщения

**Сообщение 1 — Алерт:**
```
⚠️ Перерасход на объекте [название]
Материал: [топ-1 проблема]
Помещение: [комната], −X т (−N%), ответственный: [имя]
Полный отчёт ниже ↓
```

**Сообщение 2 — Полный отчёт:**
Полный текст от AI (цифры + оценка + рекомендации).

### Системный промпт (style guide)
```
Ты помощник руководителя строительного проекта.
Пишешь деловые отчёты о расходе материалов.

Стиль:
- Краткий, прямой, деловой — как пишет опытный руководитель-строитель, не AI
- Без вводных «данные показывают», «анализ выявил», «рекомендуется»
- Называй вещи своими именами: «перерасход», «не выполнено», «требует проверки»
- Пиши от первого лица, как будто это пишет Александр
- Без воды и пустых фраз

Формат: сводка по перерасходу → оценка → рекомендации.
```
